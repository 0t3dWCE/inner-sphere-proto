# Лог проектирования локальной многоагентной AI-системы для Three.js игры через MCP

## Вводные данные и ТТХ Системы
* **Платформа:** MacBook Air M5 (24 ГБ ОЗУ, 10 CPU, 10 GPU). Пассивное охлаждение.
* **Стек проекта:** Three.js (клиентская графика, Web Audio API, WebSockets), Node.js / TypeScript / Python (бэкенд оркестратор + MCP-сервер).
* **Локальный AI-стек:** 
  * **Мозг (LLM):** Qwen 2.5 7B Instruct / Llama 3.1 8B Instruct (квантование Q4_K_M/Q5_K_M через Ollama / LM Studio).
  * **Слух (STT):** OpenAI Whisper Large-v3-Turbo / Whisper Base через `whisper.cpp` с нативной поддержкой Metal/CoreML.
  * **Голос (TTS):** Kokoro-82M (v1.0) / StyleTTS2.

## Часть 2: Проектирование MCP-структуры для NPC

Подход базируется на фабрике изолированных агентов, где одна физическая LLM принимает динамически собранный контекст конкретного персонажа.

### Пример конфигурации профилей NPC (`config/npcs.json`)
```json
{
  "bear_dragon": {
    "name": "Грр’Ток Медведракон",
    "role": "Хранитель центрального леса, древнее опасное существо",
    "personality": "Агрессивный, гордый, не терпит угроз, говорит басом, использует короткие грозные фразы.",
    "knowledge": ["Знает, что в пустыне есть оазис", "Знает, что его можно ранить только стрелами"],

  }
```

## Часть 3: ТЗ-Манифест многоагентной системы группового диалога

При нахождении в одной сцене нескольких NPC система переключается из режима «1-на-1» в режим «Многоагентного симулятора социума» со строго последовательной очередью событий (Event Loop).

### 1. Пространственный туман (Spatial Awareness)
* **Зона слышимости (Audio Radius):** Расстояние в игровых единицах Three.js (по умолчанию `R = 15`).
* Клиент вычисляет евклидово расстояние: $\Delta = \sqrt{(x_{p} - x_{n})^2 + (z_{p} - z_{n})^2}$. Все NPC с $\Delta \le R$ попадают в текущую «Комнату диалога» (`Dialogue Room`).

### 2. Механика очереди и инициативы (Turn Lock)
* Потоки генерации не должны накладываться друг на друга во избежание деградации FPS.
* Пока один персонаж обрабатывается LLM/TTS, остальные принудительно переводятся в режим `STATUS_LISTENING`.

### 3. Общая память сцены (Shared Scene Context)
Каждому агенту в промпт передается история реплик внутри комнаты, чтобы они могли реагировать не только на игрока, но и на реплики других NPC.

**Структура отправляемого JSON-контекста:**
```json
{
  "room_id": "forest_center_01",
  "history": [
    {"sender": "Player", "text": "Эй, вы двое, пошли со мной в лес! Медведракон близко."},
    {"sender": "camel_trader", "text": "Э-э, уважаемый, в лес? Мои копыта не созданы для волков. Давай лучше здесь поторгуем?"}
  ],
  "current_actor": {
    "id": "bear_dragon",
    "name": "Грр’Ток Медведракон",
    "personality": "Агрессивный, защищает лес, ненавидит верблюдов.",
    "current_state": "idle"
  }
}
```

### 4. Расширенная спецификация MCP-инструментов (Tools)

#### A. `trigger_npc_dialogue`
* **Аргументы:**
  * `text` (string): Реплика на русском языке.
  * `target` (string): Идентификатор адресата (`"player"`, `"camel_trader"`, `"all"`).
  * `continue_conversation` (boolean): флаг согласия продолжить спор/беседу без явного участия игрока.

#### B. `toggle_follow_player` (Механика Договора)
* **Аргументы:**
  * `follow` (boolean): `true` — включить режим спутника в Three.js, `false` — прекратить движение.
  * `reason` (string): Обоснование решения для игрока.

#### C. `trigger_npc_action`
* **Аргументы:**
  * `action_type` (string): `["attack", "flee", "taunt"]`.

### 5. Предотвращение зацикливания (Conversational Guardrails)
* **Максимальный лимит (Max Ticks):** Цепочка авто-ответов NPC друг другу ограничена параметром `MAX_AUTOTICKS = 3`. 
* По достижении лимита сервер принудительно возвращает управление игроку, отправляя эвент `AWAIT_PLAYER_INPUT`.
